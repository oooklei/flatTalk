# flatTalk 命中率优先 · 两层分拣优化设计

> 日期：2026-08-06  
> 状态：待用户审阅  
> 主方案：**A 路由内核优先**  
> 相关：`2026-08-04-sojourn-map-svg-design.md`（工坊资源包 / route_svg）

## 一、背景与决策摘要

系统长期成功标准包含四项：运营自助上新、对话命中率、mobile UX、可维护性。第一期必须打赢的是**命中率**；错误形态采用**两层分拣**：

1. **第一刀**：场景是否进对（跨技能串扰）
2. **第二刀**：旅居内产品类型 + 工坊线路包是否命中

备选方案曾评估「发布链路优先」「一次收齐 P0」；因第一期目标是命中率且需可独立验收「场景进对率」，选定**路由内核优先**：先止血串扰与消歧闭环，再把工坊发布索引挂到第二刀；mobile / 派单仅修挡闭环的部分。

## 二、目标与非目标

### 2.1 第一期成功标准（可验收）

| # | 标准 | 验收方式 |
|---|------|----------|
| 1 | 场景进对率提升，跨技能串扰下降 | 固定黄金用例集回归（旅居 ↔ 健康 / 找服务 / 质量评估等） |
| 2 | 消歧闭环可用 | 高歧义句 → 问清 → 用户点选或自然语言回复 → 进入正确 scene；须含端到端（含 mobile） |
| 3 | 旅居第二刀可用 | 已 **published** 的工坊线路包可按目的地/关键词稳定命中并渲染 `route_svg`；未命中显式降级并记日志 |

### 2.2 本期不做

- 地图工坊 UI / SVG 编辑器重构
- 全量清理 legacy 模板债（如历史 `route_card` 等全删）
- mobile 全面交互重构（只放行影响命中闭环的动作/脚本）
- 新技能、新大模型路由策略实验
- 将每条线路硬编码进 `intent-template-map.js`

### 2.3 长期四目标

运营自助、命中率、mobile UX、可维护性均保留；本期只把前两项目标做成可验收切片，后两项仅做不阻塞命中的最小修补。

## 三、架构：两层分拣

```
utterance
   │
   ▼
┌────────────────────────┐     高歧义      ┌─────────────────┐
│ 第一刀 · 场景门         │ ─────────────► │ 消歧问清 / 点选  │
│ score + conflict rules │ ◄───────────── │ 回写后再路由     │
│ → scene_id             │                └─────────────────┘
└───────────┬────────────┘
            │
            ▼
     scene == travel_route ?
            │否 ──► 对应技能管线（本期只修与串扰/消歧相关的缺口）
            │是
            ▼
┌────────────────────────┐
│ 第二刀 · 产品/包门      │
│ product_type           │
│ + publish index 命中   │──► sojourn-maps/{route_id} ──► route_svg
│ 未命中 → 显式降级      │
└────────────────────────┘
```

### 3.1 第一刀 · 场景门

- **职责**：只决定进哪个技能/场景（`travel_route` / 健康相关 / `find_service` / `service_quality_eval` 等）。
- **输入**：用户话语、会话上下文、现有 scoring-engine + 各 scene rules。
- **输出**：`scene_id`；必要时进入消歧状态。
- **消歧**：`ambiguity-resolver`（及编排层）必须形成闭环：展示选项 → 用户选择或 NL 回复 → 写回意图/约束 → 再次路由到正确 scene。禁止「问了等于没问」。
- **冲突**：旅居与健康 / 找服务 / 质量评估等冲突词与证据权重加固；裁决结果写入统一决策日志。
- **日志字段（最小集）**：`utterance` 摘要、候选 `scene_id` 与分数、冲突标记、是否进入消歧、消歧结果、最终 `scene_id`、时间戳。用于回归与线上对照，不要求一期做完整可观测平台。

### 3.2 第二刀 · 产品/包门（仅 travel）

- **触发条件**：仅当第一刀结果为 `travel_route`。
- **产品类型**：在现有 `inferRouteType` 演进：`wellness` | `coastal` | `culture` | `ecology`。
- **线路包**：读取发布索引，按目的地 / 关键词匹配 `data/sojourn-maps/{route_id}/`；渲染默认 `route_svg`；产品模板作补充文案/样式，**不为每条线路新建 HTML 模板**。
- **未命中**：走明确降级路径（默认推荐或本地兜底），写日志；**禁止静默落到错误线路包**。
- **多命中排序**：精确目的地匹配 > 关键词覆盖度 > `updated_at` 较新；仍无法唯一确定时，触发「选哪条线路」类消歧（属第二刀，不回退到跨技能场景门）。

### 3.3 关键边界

| 边界 | 约定 |
|------|------|
| 工坊「保存」 | 写入资源包（SVG + `route_data.json` 等），可仍为 `draft` |
| 工坊「发布」 | 写入/更新 `publish.json`（或等价），`status=published` 后第二刀才可命中 |
| 发布索引消费方 | **仅**旅居第二刀；场景门打分**不**读取发布索引，避免关键词污染跨技能路由 |
| 其它技能 | 不受第二刀影响 |

## 四、数据契约：publish.json

路径（约定）：`data/sojourn-maps/{route_id}/publish.json`  
（实现阶段若并入 `route_data.json` 扩展字段，须保持下列语义等价，并在实现计划中二选一写死。）

```json
{
  "route_id": "fcg_route_001",
  "status": "published",
  "destination": ["防城港"],
  "keywords": ["三日游", "滨海", "京族"],
  "product_type": "coastal",
  "title": "京族滨海文化三日游",
  "updated_at": "2026-08-06T00:00:00.000Z"
}
```

| 字段 | 约束 |
|------|------|
| `status` | `draft` \| `published`；第二刀只考虑 `published` |
| `destination` | 非空字符串数组；用于精确/包含匹配 |
| `keywords` | 字符串数组；可为空，但空则主要靠 destination |
| `product_type` | 四枚举之一；与产品模板/文案对齐 |
| `title` | 展示与消歧选项文案 |

**第一期不采用「保存即发布」**：须有可识别的 published 状态，避免草稿包被对话命中。工坊侧可提供显式「发布」动作，或保存流程中明确勾选发布；实现计划选定一种 UX，语义不变。

## 五、第一期落地切片

建议顺序：**S1 → S2 → S3**；**S4** 可与 S2/S3 并行。

### S1 · 消歧闭环（P0）

- 打通 ambiguity → 用户点选 / NL → 再路由。
- mobile 放行消歧相关动作与必要脚本（否则无法端到端验收）。
- **验收**：歧义黄金用例「问清后进对场景」。

### S2 · 场景门加固（P0）

- travel ↔ health / find_service / SQE 冲突词与证据权重。
- 统一路由决策日志（见 3.1）。
- **验收**：串扰用例集场景进对率达标。实现计划先跑基线，再写死阈值；默认目标为「黄金串扰用例通过率 ≥ 90%」，若基线已高于此则改为「相对基线错误用例数下降 ≥ 50%」。

### S3 · 第二刀发布索引（P0）

- 工坊侧写出 `publish.json`（或等价）；查找路径接入 map-kit / travel 管线。
- `inferRouteType` 与包查找读索引；命中 → `route_svg`；未命中显式降级 + 日志。
- **验收**：至少 N 条（实现计划定 N，建议 ≥1～3 条真实包）published 线路可被目的地/关键词稳定命中。

### S4 · 命中闭环最小修补（P1）

- mobile：仅放行影响旅居 / 消歧 / 质量评估等**挡闭环**的动作与脚本问题。
- dispatch `actions_allowed`：仅当缺口导致错路由或死交互时修；否则后置。
- 不清全量 legacy 模板债。

## 六、测试与 Done 定义

### 6.1 黄金用例集（本期必须附带最小集）

三类用例，可放在 `docs/` 或 `scripts/` 测试清单中，实现计划指定路径：

1. **串扰**：表面像旅居实为健康/找服务/SQE，及反向。
2. **消歧**：双场景高分歧义 → 问清 → 进对。
3. **线路命中**：对已 published 包的目的地/关键词 → 正确 `route_id` + `route_svg`；未发布包不得命中。

### 6.2 第一期 Done

同时满足：

1. 消歧用例端到端通过（含 mobile 关键路径）。
2. 串扰用例场景进对率达实现计划所定阈值。
3. 至少约定数量的 published 工坊包可稳定命中；未命中有降级与日志。

## 七、风险与对策

| 风险 | 对策 |
|------|------|
| 运营只保存不发布，对话命不中 | 文档 + 工坊标明 draft/published；第二刀只读 published |
| 发布索引被第一刀误用导致串扰 | 硬约束：场景门不读 publish 索引 |
| 后端消歧修好、端上剥脚本导致假闭环 | S1/S4 绑定端到端验收，禁止只测 API |
| 无用例集无法宣称命中率提升 | 本期强制附带最小黄金用例 |
| 范围膨胀 | legacy 全删、工坊 UI、SQE 深改一律后置 |
